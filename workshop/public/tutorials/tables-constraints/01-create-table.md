## Objetivo del paso

Vas a crear tablas desde cero. Al terminar sabrás:

1. La forma de `CREATE TABLE`: columnas, tipos y la clave primaria.
2. Cómo generar los `id` automáticamente con `GENERATED ... AS IDENTITY`.
3. Valores por defecto con `DEFAULT`.
4. Borrar una tabla con `DROP TABLE`, y por qué a veces no se puede.

## `CREATE TABLE`

```sql run title="Una tabla de proveedores"
CREATE TABLE suppliers (
  id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  name text NOT NULL,
  email text,
  country text NOT NULL DEFAULT 'España',
  created_at timestamptz NOT NULL DEFAULT now()
);
```

Abre el panel **Datos**: la tabla `suppliers` ya aparece, vacía. Cada línea define una columna con su **nombre**, su **tipo** y, opcionalmente, sus **restricciones**.

:::tip Convenciones de nombres
- Tablas en **plural** y en `snake_case`: `suppliers`, `order_items`.
- Columnas en `snake_case`: `created_at`, `customer_id`.
- La clave primaria se llama `id`; una clave foránea, `<tabla en singular>_id`.

No hay una única convención correcta; lo importante es usar **siempre la misma** en todo el esquema.
:::

## La clave primaria generada

`id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY` hace dos cosas:

- `PRIMARY KEY`: la columna es única y no admite `NULL`.
- `GENERATED ALWAYS AS IDENTITY`: PostgreSQL asigna el siguiente número automáticamente.

```sql run title="Insertar sin indicar el id"
INSERT INTO suppliers (name, email)
VALUES ('Distribuciones Norte', 'ventas@norte.example')
RETURNING id, name, country, created_at;
```

:::postgres ALWAYS, BY DEFAULT y serial
- `GENERATED ALWAYS AS IDENTITY`: la base de datos **siempre** genera el valor; si intentas indicar uno a mano, da error. Es lo más seguro.
- `GENERATED BY DEFAULT AS IDENTITY`: lo genera si no indicas uno. La tienda lo usa para poder cargar sus datos de ejemplo con ids concretos.
- `serial`: la forma antigua de PostgreSQL. Sigue funcionando, pero en tablas nuevas usa `IDENTITY`, que es SQL estándar.
:::

## Valores por defecto

`DEFAULT` da valor a una columna cuando el `INSERT` no la menciona. En el ejemplo, `country` vale `'España'` y `created_at` el momento de la inserción (`now()`). Es la forma habitual de registrar **cuándo** se creó cada fila, sin depender de que la aplicación lo envíe.

:::tip timestamptz para los instantes
Para "cuándo pasó algo" usa `timestamptz` (*timestamp with time zone*): PostgreSQL guarda el instante exacto y lo muestra en la zona horaria de cada conexión. Con `timestamp` a secas, dos servidores en zonas distintas interpretarían la misma hora de forma diferente.
:::

## Errores habituales

Crear una tabla que ya existe es un error:

```sql run error title="Crear dos veces la misma tabla"
CREATE TABLE categories (
  id integer PRIMARY KEY,
  name text
);
```

Y no se puede borrar una tabla de la que dependen otras: `products.category_id` apunta a `categories`.

```sql run error title="Borrar una tabla de la que dependen otras"
DROP TABLE categories;
```

`DROP TABLE` sí funciona con una tabla de la que nada depende, como la de proveedores que acabas de crear:

```sql run title="Borrar la tabla de proveedores"
DROP TABLE suppliers;
```

:::warning DROP TABLE no tiene vuelta atrás
`DROP TABLE` borra la tabla **y todos sus datos**. Existe `DROP TABLE ... CASCADE`, que además borra lo que depende de ella (por ejemplo, las claves foráneas que la referencian): úsalo solo si sabes exactamente qué arrastra.
:::

## Retos

::::challenge Tabla de proveedores
Crea la tabla `suppliers` con estas columnas (y solo estas):

- `id`: entero, clave primaria generada automáticamente.
- `name`: texto, obligatorio.
- `email`: texto, opcional.
- `country`: texto, obligatorio, con valor por defecto `'España'`.

```sql verify
SELECT 'columna ' || column_name AS item,
       data_type || CASE WHEN is_nullable = 'NO' THEN ', obligatoria' ELSE '' END AS outcome
FROM information_schema.columns
WHERE table_schema = 'public' AND table_name = 'suppliers'
UNION ALL
SELECT 'proveedor sin nombre', workshop.try($$INSERT INTO suppliers (email) VALUES ('a@b.example')$$)
UNION ALL
SELECT 'proveedor sin email', workshop.try($$INSERT INTO suppliers (name) VALUES ('Acme')$$)
UNION ALL
SELECT 'país por defecto', workshop.try($$INSERT INTO suppliers (name) VALUES ('Acme')$$, $$SELECT country FROM suppliers WHERE name = 'Acme'$$)
UNION ALL
SELECT 'id generado', workshop.try($$INSERT INTO suppliers (name) VALUES ('Acme')$$, $$SELECT (id IS NOT NULL)::text FROM suppliers WHERE name = 'Acme'$$);
```

:::hint
`id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY` (también vale `BY DEFAULT`).
:::

:::hint
Para la última columna: `country text NOT NULL DEFAULT 'España'`.
:::

:::solution
```sql
CREATE TABLE suppliers (
  id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  name text NOT NULL,
  email text,
  country text NOT NULL DEFAULT 'España'
);
```
La corrección intenta insertar proveedores sin nombre (debe fallar por `not null`), sin email (debe funcionar) y comprueba el país por defecto y el `id` generado.
:::

::::challenge Tabla de etiquetas
Crea la tabla `tags` para etiquetar productos ("oferta", "novedad"…), con:

- `id`: entero, clave primaria generada automáticamente.
- `name`: texto, obligatorio.

```sql verify
SELECT 'columna ' || column_name AS item,
       data_type || CASE WHEN is_nullable = 'NO' THEN ', obligatoria' ELSE '' END AS outcome
FROM information_schema.columns
WHERE table_schema = 'public' AND table_name = 'tags'
UNION ALL
SELECT 'etiqueta válida', workshop.try($$INSERT INTO tags (name) VALUES ('oferta')$$)
UNION ALL
SELECT 'etiqueta sin nombre', workshop.try($$INSERT INTO tags (name) VALUES (NULL)$$);
```

:::solution
```sql
CREATE TABLE tags (
  id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
  name text NOT NULL
);
```
¿Debería poder haber dos etiquetas "oferta"? Probablemente no. En el siguiente paso aprenderás a impedirlo con `UNIQUE`.
:::
::::

:::recap
- `CREATE TABLE nombre (columna tipo restricciones, ...)` crea una tabla.
- `id integer GENERATED ALWAYS AS IDENTITY PRIMARY KEY`: clave primaria generada por la base de datos (preferible a `serial`).
- `DEFAULT` da un valor cuando no se indica; `created_at timestamptz NOT NULL DEFAULT now()` registra cuándo se creó cada fila.
- `DROP TABLE` borra la tabla y sus datos; falla si otras tablas dependen de ella.

En el siguiente paso añadirás las reglas que protegen los datos: `UNIQUE`, `CHECK` y claves foráneas.
:::
